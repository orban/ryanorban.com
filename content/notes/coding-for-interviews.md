## Summary

[Coding for Interviews](/notes/coding-for-interviews/) was a weekly newsletter run by Parker Phinney that provided algorithm and programming challenge exercises to help software engineers prepare for technical interviews. The linked books page curated the canonical references for interview preparation in 2013.

Technical interview culture at large tech companies (Google, Facebook, Amazon, Microsoft) in 2013 had fully standardized around algorithmic whiteboard problems — a genre that would later generate significant criticism but was then the dominant hiring signal. The canonical books for this preparation had emerged: Cracking the Coding Interview by Gayle Laakmann McDowell (referenced via Atwood, given the URL fragment `#atwood` — likely Jeff Atwood, co-founder of Stack Overflow), Introduction to Algorithms (CLRS), The Algorithm Design Manual by Steven Skiena, and Programming Interviews Exposed.

The newsletter format worked well for this use case: regular small problems that build the pattern-recognition muscles for recognizing dynamic programming situations, graph traversal opportunities, and binary search applicability — the core algorithmic vocabulary of technical interviews.

## Key points

- Cracking the Coding Interview by Gayle Laakmann McDowell was the dominant interview prep book — structured by company and problem type
- CLRS (Introduction to Algorithms) was the academic reference; Skiena's Algorithm Design Manual was the practitioner bridge
- Technical interviews in 2013 were almost entirely whiteboard algorithmic problems — a pattern that has since diversified toward system design and practical coding
- The URL `#atwood` suggests a Jeff Atwood (Stack Overflow) connection — possibly a recommendation embedded in an Atwood blog post
- The newsletter model for SKILL-building (one problem at a time) predates the platform era — LeetCode and HackerRank would later dominate this space
