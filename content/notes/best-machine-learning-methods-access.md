## Summary

By late 2013, the barriers to using state-of-the-art machine learning methods had dropped dramatically. scikit-learn provided implementations of dozens of algorithms with a consistent API; Apache Spark's MLlib brought distributed ML to commodity clusters; cloud services from Amazon AWS and Google Cloud made compute available on-demand without capital expenditure. The question [[can I use [method X]?]] was less often about technical access and more often about whether you had the data and problem definition.

This piece from Strata (O'Reilly's data conference brand) reflected the prevailing optimism of the period: the tools are here, the compute is accessible, the algorithms are open-sourced. The gap was talent — people who understood both the methods and the domain problems well enough to apply them usefully. That talent gap was what Zipfian Academy and similar programs were attempting to fill.

The flip side, underappreciated in 2013, was that access to methods doesn't automatically translate to good outcomes. [Cargo cult analytics](/notes/cargo-cult-analytics/) (running algorithms because they're available) was already a pattern. The why machine learning fails literature was pointing out that access was not the bottleneck — judgment, problem formulation, and data quality were.

## Key points

- By 2013, the barriers to state-of-the-art machine learning had become: data quality, domain expertise, and problem formulation — not algorithmic access.
- scikit-learn unified dozens of algorithms under one consistent Python API; MLlib brought distributed ML to Hadoop/Spark clusters.
- Cloud compute (AWS, Google Cloud) eliminated the hardware barrier for most practitioners.
- The optimism of this moment (access is democratized!) was real but incomplete — access without judgment produces [cargo cult analytics](/notes/cargo-cult-analytics/).
- Zipfian Academy was part of the talent-gap response: training people to use the accessible tools well.
