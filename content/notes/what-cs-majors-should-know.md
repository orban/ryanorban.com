## Summary

Matt Might (then a professor at the University of Utah) wrote this canonical essay as a guide to the breadth and depth a CS graduate should have. It covers a remarkable range: from Unix proficiency and the command line to formal languages and automata theory, from data structures and algorithms to systems programming, operating systems, networks, security, and software engineering practice. The essay's tone is prescriptive but pragmatic — these aren't theoretical ideals, they're the things that separate a practitioner who can reason about hard problems from one who can only apply known patterns.

Several threads run through Might's framework: deep systems programming knowledge (C, memory management, performance), theoretical foundations (type theory, lambda calculus, formal proofs), and practical software engineering skills (version control, testing, code review). He argues that proficiency in all three categories is necessary for real competence. It's easy to find engineers who are strong in one and weak in the others.

The essay circulated widely in 2013 because it matched a moment when many developers were self-taught or had emerged from bootcamps, and the question of what "real" CS knowledge meant was live. Might wasn't gatekeeping — the essay explicitly notes that self-taught programmers can and should close these gaps — but it provides a concrete map for doing so.

## Key points

- Unix and command-line fluency as a baseline: the ability to write shell scripts, use pipes, and navigate the filesystem without a GUI is foundational for most technical work.
- Algorithms and data structures: not just knowing them but understanding when they apply — complexity analysis and the ability to choose the right tool for scale.
- Systems programming: memory, pointers, cache effects, the gap between source code and machine behavior — matters for performance-critical work anywhere in the stack.
- Formal methods: lambda calculus, type systems, automata theory — gives you the vocabulary to reason about programming languages and verification.
- Portfolio over transcript: Might argues that demonstrated projects carry more weight than coursework, pushing back on credentials as the primary signal.
