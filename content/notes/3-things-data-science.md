## Summary

This KDnuggets piece (likely from the Galvanize / Zipfian Academy orbit given the 2015 save context) describes the gap between academic data science education and what practitioners actually encounter day-to-day. The three things that don't appear in textbooks tend to cluster around the same insight: data science is a sociotechnical practice, not just a technical one.

The first is data wrangling time. The commonly cited figure — 80% of a data scientist's time is spent cleaning and preparing data — turns out to be accurate not because of incompetence but because production data is genuinely messy. Schema changes, logging inconsistencies, encoding issues, and missing values are structural features of how real systems work, not exceptions. No textbook can simulate this because it requires working with real production systems over time.

The second is communication. A technically correct model that nobody understands or trusts is worthless. Data scientists who can explain their work to non-technical stakeholders — and who can push back on requests that would produce misleading results — are dramatically more effective than those who can't. This is a SKILL textbooks don't teach because it requires domain knowledge and organizational context, not just statistics.

The third is the gap between a working model and a deployed one. Model deployment involves software engineering skills, infrastructure decisions, monitoring, and organizational coordination that are entirely separate from model building. In 2015, this gap was particularly wide — the MLOps tooling that now handles much of this didn't exist yet.

## Key points

- 80% of time on data wrangling is structural, not accidental — production data is genuinely messy.
- Communication skills separate effective data scientists from technically correct but useless ones.
- Model deployment gap: working locally ≠ deployed and monitored in production.
- Textbooks teach techniques; practices require working in real organizations with real data.
- Organizational politics: getting buy-in for data-driven decisions is a distinct skill from building models.
- Reflects the Galvanize curriculum gap analysis: what bootcamp students needed beyond algorithms.
