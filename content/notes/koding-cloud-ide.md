## Summary

Koding was a cloud-based IDE and development environment launched around 2012, giving developers a full Linux environment accessible from the browser — terminal, code editor, and running server processes in one place. The original tweet captured the excitement of early beta access: "a new way for developers to work."

The core value proposition: eliminate the setup overhead of local development environments. Instead of configuring [Node.js](/notes/nodejs/), Python, Ruby, and their dependencies locally, you get a pre-provisioned cloud VM that runs your code immediately. This was genuinely useful in 2012 when cross-platform development environment setup was painful and laptop specs were lower.

Koding was ahead of its time. The concept required browser-based terminal and code editing to work well, which depended on web technology maturing further. It predated GitHub Codespaces (2020), Gitpod (2019), and Replit (growing from 2016) by years. Koding eventually pivoted to enterprise team development environments before being acquired. The category it defined — ephemeral cloud development environments — became mainstream a decade later, driven partly by the shift to remote work in 2020.

## Key points

- Koding (2012): browser-accessible Linux VM with terminal + code editor — full development environment in the cloud
- Core value: eliminate local environment setup friction; start coding immediately from any machine
- Predated GitHub Codespaces, Gitpod, Replit — the same concept, 8-10 years earlier
- Struggled with the web technology limitations of 2012 (browser terminals were rough); the category needed WebSockets and better editor tech to mature
- Koding pivoted to enterprise team IDEs and was eventually acquired; the consumer cloud IDE space it pioneered went mainstream circa 2020
