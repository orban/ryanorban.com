## Summary

In 2012, Backbone.js (by Jeremy Ashkenas, released 2010) was the dominant JavaScript MVC framework for building single-page applications. But the space was moving fast — alternatives were emerging with different tradeoffs around data binding, template systems, and conventions-vs-configuration. This roundup catalogs the contenders.

The major alternatives at the time: Ember.js (convention-over-configuration, opinionated, influenced by Rails), Knockout.js (Microsoft-backed, declarative data binding with observables), AngularJS v1 (Google, two-way binding, directives), Spine.js (lighter than Backbone, [CoffeeScript](/notes/coffeescript/)-friendly), CanJS (pragmatic, focused on performance), and Batman.js (Rails-like conventions).

Seen from 2026, the landscape looks dramatically different. AngularJS won the early wave, then React (released 2013) changed the model entirely — from MVC frameworks to component trees with unidirectional data flow. Ember survived, Vue.js emerged, and most of the 2012 contenders are abandoned. The 2012 framework proliferation was a symptom of the field not yet having discovered the component model that React would articulate.

## Key points

- 2012 was peak JavaScript MVC framework proliferation — before React reframed the problem
- Backbone.js was lightweight and minimal; its alternatives were more opinionated or feature-rich
- Ember.js: Rails-influenced conventions; Knockout.js: MVVM data binding; AngularJS: two-way binding with directives
- React (2013) invalidated most of this competition by redefining the unit of composition as the component
- Historical artifact: shows how rapidly JS frontend shifted from choose your MVC to React or alternatives to React
