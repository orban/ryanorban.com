## Summary

*Shit for Making Websites* (shitformakingwebsites.com) was a one-page web resource aggregator from 2013 that collected tools, CSS frameworks, fonts, icon sets, color pickers, stock photo sites, and other assets useful for building websites. The deliberately irreverent name was part of its appeal — it cut through the noise of SEO-optimized top 10 web design tools articles with a direct, no-franding curation.

Sites like this filled a real gap in 2013: there was no centralized package registry for web design resources. npm existed but was Node-focused; there was no equivalent for front-end design assets and tools. The Bootstrap CSS framework had just hit version 2 (early 2012), and the front-end ecosystem was fragmenting into dozens of grid systems, icon libraries, and JavaScript plugins that weren't easy to discover through search.

The format — a single long page with categorized links — was the precursor to GitHub's awesome lists pattern (which emerged in late 2014 with Sindre Sorhus's awesome-* repos). The irreverent naming also reflects the aesthetic sensibility of the early 2010s web design community, which used platforms like Hacker News, Dribbble, and personal blogs to share tools peer-to-peer.

## Key points

- Curated single-page resource lists: a community pattern before GitHub's awesome-list format standardized it in 2014.
- Reflected the fragmented 2013 front-end ecosystem: no npm-for-design, no centralized registry for CSS frameworks and UI assets.
- Bootstrap and the grid framework era: dozens of competing CSS grid systems, icon fonts (Font Awesome, Glyphicons), and UI kits — discovery was the real problem.
- Irreverent naming as signal: deliberately non-corporate, peer-curation aesthetic that characterized the early 2010s web design community.
