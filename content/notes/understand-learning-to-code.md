## Summary

Dave Fayram's 2012 post pushed back against the then-nascent everyone should learn to code wave — specifically against advocates who promoted programming literacy without understanding what the SKILL actually requires in practice. The Learn to Code movement was gaining momentum in 2012, with Codecademy launching the previous year and figures like Michael Bloomberg pledging to learn to code. The post wasn't anti-learning, but anti-magical-thinking about the ease and universality of the skill.

The distinction Fayram drew: programming as a powerful tool for specific purposes versus programming as a universal skill everyone needs. Many of the learn to code arguments treated it like literacy — something everyone should have. But programming has high variance in both aptitude and payoff. Someone building a small script to automate their work gets enormous value. Someone grinding through a course to prove they can code but never using it productively gets very little. The question isn't "should more people learn to code (probably yes) but what should they expect to get out of it and what does it actually take."

This was part of a broader debate in 2012-2013 about tech education and coding bootcamps, which were just emerging. Codecademy, General Assembly, and similar programs were betting that programming was learnable at scale and broadly applicable. The skeptical position (which this post represents) turned out to be partly right — many bootcamp graduates struggled to find jobs, and the 10 weeks to career change narrative was often oversold.

## Key points

- The "learn to code" movement often conflated coding literacy (scripting for personal use) with [professional programming](/notes/professional-programming/) (building systems at scale).
- Understanding what you're asking people to learn matters — the difficulty and required commitment vary enormously by goal.
- Codecademy (launched 2011), General Assembly, and others were the practical infrastructure for the movement.
- Contrast with Zed Shaw's Learn Code the Hard Way — which explicitly told people it was hard and required grinding.
- Related debate: STEM education priorities and whether programming specifically should be required in schools.
