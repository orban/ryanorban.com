## Summary

These slides capture a talk by Ryan Orban at Galvanize addressing a real organizational friction of the mid-2010s: data scientists and software engineers often couldn't collaborate effectively, even when working on the same product. The gap had multiple dimensions — different tooling (R vs. Python vs. Java), different workflows (exploratory vs. production-oriented), different success metrics (model performance vs. system reliability), and different mental models about what "done" means.

The talk frames this as a team design and communication problem rather than a technical one. Data scientists trained in research settings often lacked software engineering practices (version control, testing, code review). Engineers didn't understand the exploratory, hypothesis-driven nature of machine learning work. The proposed solution involves hybrid roles, shared vocabulary, and explicit interface contracts between the two functions.

This tension defined the rise of the machine learning engineer role — a hybrid position that emerged precisely because neither pure data scientists nor pure engineers could cover the full pipeline from research to production. The talk predates the current MLOps framing but covers the same underlying organizational problem.

## Key points

- Core friction: different tooling, workflows, and success metrics between data science and software engineering.
- Data scientists lacked engineering practices; engineers didn't understand exploratory ML workflows.
- Solution: hybrid roles, shared vocabulary, explicit interface contracts.
- Precursor to the machine learning engineer role and MLOps discipline.
- Delivered at Galvanize during the talent shortage when the DS/engineering gap created real product bottlenecks.
