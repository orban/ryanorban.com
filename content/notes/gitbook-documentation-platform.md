## Summary

GitBook launched in 2014 as a tool for creating books and documentation from Markdown files stored in a Git repository. The pitch was simple: write in Markdown, push to Git, get a cleanly rendered book on the web. This fit naturally with how developers already worked and made technical writing feel less foreign.

The timing coincided with a broader shift toward documentation-as-code: treating docs with the same version control, review, and collaboration workflows as software. GitBook made this practical for teams that didn't want to set up custom static site generators. It was especially popular for open source project documentation, API references, and the kind of multi-author technical books (The Flask Mega-Tutorial had a following that would have benefited from this).

GitBook later pivoted significantly — by the late 2010s it became a more conventional wiki/documentation platform and moved away from the Git-native workflow. The 2014 version was the more opinionated, developer-focused tool.

## Key points

- Write documentation in Markdown, store in Git, publish automatically to a clean web interface.
- Documentation-as-code philosophy: docs treated like software with version control and collaboration.
- Natural fit for open source project docs, API references, and technical books.
- Used by many data science and developer tool projects in 2014-2016 before the pivot.
- Later became a general-purpose wiki tool, losing its Git-native character.
