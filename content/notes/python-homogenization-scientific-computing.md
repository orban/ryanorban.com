## Summary

This R-Bloggers post argues that Python was consolidating scientific computing in 2014 — gradually absorbing workloads previously split across R, MATLAB, Stata, and SAS. The core argument: Python wasn't better than each specialist language in its own domain, but it was good enough at everything while offering a unified ecosystem. A statistician who learned pandas and scikit-learn could also write web services, automate pipelines, and build prototypes — things R couldn't do without ugly hacks.

The post is a snapshot of a real transition. By 2014, NumPy, SciPy, matplotlib, pandas, and scikit-learn had reached a critical mass that made the just use R for stats argument harder to defend in applied data science contexts, even if R's statistical packages remained deeper in many specific areas.

## Key points

- Python's advantage wasn't any single capability — it was breadth: one language for data manipulation, modeling, visualization, web services, and automation
- NumPy and SciPy solved the core numerical computing gap that had kept scientists on MATLAB
- pandas made tabular data manipulation competitive with R's data frame model
- The ecosystem effect compounded: more users meant more libraries, better documentation, and faster bug fixes
- The post acknowledges R's statistical depth (CRAN packages, specialized methods) but predicts Python will eventually match it — which broadly happened
