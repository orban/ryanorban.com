## Summary

DHH (David Heinemeier Hansson, creator of Ruby on Rails and co-founder of 37signals) wrote this essay in November 2012 as Twitter was systematically closing off its ecosystem. Twitter had just introduced restrictive API guidelines that capped third-party client user counts, cut off competitors from the Twitter firehose, and made clear that the open platform era was ending.

The extractive framing is the essay's key contribution: Twitter had *extracted* enormous value from the developer ecosystem — free clients (Twitterrific, Tweetbot, Echofon), third-party services (Hootsuite, CoTweet), innovation in interfaces — and was now shutting it down after the ecosystem had served its purpose of growing the network. The developers who built on Twitter's platform received no compensation for the value they generated and no warning before the rules changed.

DHH's essay was part of a wave of writing that crystallized the platform risk concept for developers — building on someone else's API creates a dependency that the platform can monetize or cut at will. Dalton Caldwell's critique (from inside — he built App.net as a Twitter alternative) and Marco Arment's essays on the same topic all appeared in this 2012 window. The pattern has since repeated: Apple, Google Play, Facebook, Twitter, and later Reddit's 2023 API changes all followed the same arc.

## Key points

- Twitter went from open ecosystem to extractive platform by capping third-party client users at 100k tokens
- DHH's "extractive" framing: Twitter used developers to grow the network, then cut them off when the network reached scale
- Platform risk: building on third-party APIs creates value for the platform owner who can terminate access unilaterally
- 2012 was the inflection: Tweetbot, Twitterrific, and other clients were effectively sentenced to slow death
- The pattern repeats: Facebook (2014-2018 API tightening), Reddit (2023 API pricing) — the same arc
