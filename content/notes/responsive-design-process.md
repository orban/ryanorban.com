## Summary

[Responsive web design](/notes/responsive-web-design/) (a term coined by Ethan Marcotte in his 2010 A List Apart article and book) was becoming mainstream by 2012. The core technique — CSS media queries that adjust layout based on viewport width, combined with fluid grids and flexible images — meant websites could adapt to phones, tablets, and desktops from a single codebase. Smashing Magazine and the UX design community were working through what this meant for design process.

The fixed-canvas design workflow — designers working in Photoshop at 1024×768, handing off pixel-perfect comps to developers — broke down completely in the responsive era. A design comp only captured one breakpoint. The UX Design article argued for process changes: mobile-first design (starting with the smallest screen and expanding, forcing prioritization), content inventory before wireframing, and closer collaboration between designers and developers since layouts needed to be understood as systems, not static images.

Style tiles (Samantha Warren) and element collages (Dan Mall) emerged as lighter-weight alternatives to full-page Photoshop comps — showing typography, color, and component design without locking in a specific layout. Pattern libraries became design artifacts rather than just developer resources.

## Key points

- [Responsive web design](/notes/responsive-web-design/): CSS media queries + fluid grids + flexible images — one codebase for all screen sizes.
- Ethan Marcotte's 2010 A List Apart article named and defined the approach; 2012 saw it becoming industry standard.
- Design process breakdown: fixed-canvas Photoshop comps don't capture responsive behavior — need systems thinking.
- Mobile first (Luke Wroblewski): design smallest screen first to force prioritization; then expand.
- Style tiles, element collages, pattern libraries as responsive-era design artifacts replacing static comps.
