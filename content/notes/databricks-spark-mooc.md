## Summary

In December 2014, Databricks announced two MOOCs on Apache Spark in collaboration with BerkeleyX and edX. This was a deliberate adoption play: Spark was nascent (it had just hit 1.0 in May 2014), and making high-quality education freely available was the fastest way to grow the ecosystem and displace Hadoop MapReduce as the default big data processing framework.

Databricks was the company built by the original Spark creators at UC Berkeley's AMPLab. The founders — including Matei Zaharia — had the academic credibility to produce rigorous courses, and the commercial incentive to make Spark ubiquitous. The edX course model lowered the barrier to learning distributed computing for data scientists who had Python and SQL backgrounds but hadn't touched the JVM.

Apache Spark's core proposition over Hadoop MapReduce in 2014: in-memory computation (100x faster for iterative algorithms), a unified API spanning batch, streaming, SQL, and ML, and Python/Scala/Java language support. The MLlib library brought distributed machine learning to the same framework, letting data scientists run k-means, logistic regression, and collaborative filtering on clusters without writing Java MapReduce jobs.

## Key points

- December 2014: Databricks launches Spark MOOCs on BerkeleyX/edX — a deliberate ecosystem growth strategy.
- Apache Spark 1.0 had just shipped in May 2014 — these courses were seeding adoption at the critical early moment.
- Spark vs Hadoop MapReduce: in-memory processing, unified API (batch + streaming + SQL + ML), Python-friendly.
- Databricks founded by UC Berkeley AMPLab researchers including Matei Zaharia.
- MLlib: Spark's built-in distributed machine learning library — k-means, logistic regression, collaborative filtering.
- This moment precedes Spark's dominance — by 2016 it had largely displaced MapReduce for new projects.
