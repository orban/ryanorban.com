## Summary

Data Community DC published this getting-started guide at a pivotal moment in 2013: Python was in the process of decisively winning the data science language debate against R, MATLAB, and SAS. The DC data science meetup community — practitioners, not academics — was a reliable signal of what was actually being used in industry.

The standard Python data science stack in early 2013 consisted of: NumPy for numerical computing and array operations, Pandas for tabular data manipulation (inspired by R's data frames), matplotlib for visualization, and scikit-learn for machine learning. IPython (predecessor to Jupyter) provided an interactive shell that made exploratory analysis feel natural. The guide likely walked through installing these (probably via Anaconda or manual pip installs) and demonstrating the basic workflow.

What made Python win over R for many practitioners: general-purpose language (so the same language used for web scraping, ETL pipelines, API integration), a cleaner syntax for complex logic, and growing library support. R remained dominant in academia and statistics; Python took data engineering, production ML, and full-stack data work.

## Key points

- The 2013 Python data science stack: NumPy, Pandas, matplotlib, scikit-learn, IPython — the same core stack (now via Jupyter) still dominant today
- Pandas was relatively new (created by Wes McKinney in 2008, first release 2009) but already the standard for tabular data in 2013
- Anaconda was emerging as the standard Python distribution for data science — solving the painful dependency management of the era
- scikit-learn unified classical machine learning under a consistent `fit/predict` API — foundational to how ML is practiced in Python
- Data Community DC represented the practitioner layer: engineers and analysts doing applied data work, not academic researchers
