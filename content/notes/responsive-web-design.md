## Summary

This piece by Simon Foster addresses the emerging role of the responsive designer in 2012 — two years after Ethan Marcotte coined [responsive web design](/notes/responsive-web-design/) in his seminal 2010 A List Apart article. By late 2012, responsive design had shifted from a novel technique to a near-requirement, driven by the rapid growth of mobile browsing. The question was no longer *whether* to design responsively but *how* to organize the design process around it.

[Responsive web design](/notes/responsive-web-design/) combines three techniques: fluid grids (proportional layout columns), flexible images (max-width scaling), and CSS media queries (style rules conditional on viewport size). Ethan Marcotte's 2011 book codified these into a design methodology. The challenge Foster and others were navigating in 2012: design tools (Photoshop, still dominant) weren't built for fluid layouts, and mobile-first thinking required inverting the traditional desktop-first design process.

The mobile-first principle — design for the smallest screen first and scale up rather than down — was Luke Wroblewski's contribution, also from 2011. By 2012 this was the emerging best practice but required real process change: wireframes, comps, and handoff to developers all needed to account for multiple breakpoints. The "responsive designer" of Foster's title was someone who internalized this fluid thinking.

## Key points

- [Responsive web design](/notes/responsive-web-design/): fluid grids + flexible images + CSS media queries — coined by Ethan Marcotte (2010)
- Mobile-first design principle (Luke Wroblewski, 2011): design for mobile constraints first, enhance for desktop
- 2012 was the inflection point: responsive went from technique to expectation for new web projects
- Design tool gap: Photoshop fixed-pixel comps didn't map to fluid responsive layouts — a workflow problem
- Led to CSS frameworks (Bootstrap, Foundation) that made responsive grids easier to implement
